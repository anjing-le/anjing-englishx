# 校对与逐句角色覆盖

2026-11-04，本地预览。当前完成两个可用环节：角色分析逐句覆盖，以及校对后保存新版本、重建分析。音色/声纹、音频说话人分离、自动按声音切段、独立音素强制对齐仍未实现。

## 使用流程

⌘, → 校对当前学习片段。校对的是已入库的当前片段或本次加工结果，不是尚未加工的待导入文件。

- 选择一句，播放该句或点词试听。
- 修改原话后点“更新词表”。词数相同时保留已有估计时间供核对；词数变化时，只保留未变前后缀的时间，中间新词的时间留空。需显式补齐，不能按字数猜。
- 在某个词之后分句；下一句不继承已确认的说话人。也能与下一句合并。词 ID、已有时间保持不变。
- 角色名可填写或留空。只有主动确认/编辑的角色才作为校对指定，未动的自动建议不会被升级成人工结论。
- 时间以秒填写，检查非数值、NaN、倒序、重叠、超过视频，以及未同步的原话。输入未通过检查时不能保存。
- 返回设置会保留本次会话中的草稿；“还原修改”恢复到打开时的状态。尚无跨客户端重启的草稿持久化。
- “保存并更新分析”明确启动模型任务：用校对后的分句和时间重新抽帧分析角色，应用显式角色覆盖，然后重建全片逐词讲解。生成全新片段版本，原包保留。停止或失败不替换原片段。

原话、分句和时间的校对不是模型校正承诺。全片仍为 needs-review，未自动升级成已经验收的学习材料。

## 数据边界

校对 UI 读取验证过的 clip.json，提交原包 SHA256、分句、词 ID/文本/时间、角色名及显式确认状态。请求中没有旧讲解。review.py 只接受当前库内的原包，校验父版本哈希和词表，保存 parentPackageID / sourceManifestSHA256 / reviewEditsSHA256 / revisedAt / revisionSource=manual-editor-v1。发布前再次检查原包哈希。

自动角色分析仍只接受 high / uncertain / unknown。只有校对 worker 能在显式覆盖后写 manual / reviewSource=user；Swift 读取端要求 manual-editor-v1 的版本来源才接受 manual 归属。这里 user 表示校对入口提交的显式指定，不是一个可认证的人类审核签名。测试副本中的指定不代表用户已经确认了正式材料。

新包保留原媒体、源包快照、原识别/时间/角色结果引用、校对请求、新抽帧、提示词副本与新讲解。旧讲解不跨文本版本复用；没有把原来一个词的时间按比例分给新增词。

角色提示词 characters-v2 以每句 3 帧、每批最多 8 句/24 帧处理所有分句，携带已建立的角色表。客户端严格检查跨批身份冲突；名字/作品相同的局部 ID 可归一，同一个旧 ID 不能改成另一个人物。角色依据不足时仍保留未知。
