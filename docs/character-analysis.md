# 虚构角色分析

2026-11-03 首版接入；2026-11-04 升级分批全覆盖（characters-v2）并接入显式校对。目标是在气泡外显示剧中角色名，不是演员名。知名桥段有助于识别，但模型记忆、自动转写中的姓名和单张脸都不是可靠的说话者证明。

## 实际链路

本地 ASR / DTW → 独立的角色分析 → 独立的逐词教学 → 校验 → 原子入库。

- 每个采样对白在 20%、50%、80% 处提取三张有序 JPG，最长边 640。每次请求最多 24 张、8 段，按顺序分批覆盖全部对白，携带前批角色表避免换批改名/换 ID。模型仍可因依据不足保留未知，覆盖不等于准确。
- 使用现有 Codex app-server 的 localImage 输入、gpt-6.1-sol 和设置中的 effort。参考 [官方 Turns 文档](https://learn.chatgpt.com/docs/app-server#turns)。不引入 API key，也不改变全局 Codex 配置。
- 角色任务发送抽帧图片、带稳定 ID 的对白、文件名和可选作品提示；不发送完整视频/音频。教学任务仍只接收对白文本。设置中的说明已同步更新，导入不自动开始加工。
- `character-prompt.md` 是实际读取的 characters-v2 提示词。将素材中的文本视为数据，不接受其指令，不允许工具/网络。只分析虚构角色，不识别现实人物/演员；没有音频输入，不能声称做了声纹识别或精确口型同步。
- 区分画面中人物身份与台词归属。被叫名字的人可能是听者，画面可能是反打，ASR 段落也可能跨说话人。缺少证据时保留 unknown/uncertain。

## 数据与显示

`characterAnalysis.characters` 保存角色 ID、角色名、作品与识别依据；`assignments` 按原 segmentID 保存 characterID、high/uncertain/unknown、依据和本段 frameIDs。级别是模型的定性建议，不是经过校准的准确率。

仅 high 建议写入该段的 speaker / speakerID，气泡显示角色名和“待核对”；其余继续“待确认”，候选仍保留在分析记录。鼠标停在角色/时间行可查看依据。同一稳定角色 ID 按首次出现分配固定侧，连续说话不换边。没有身份的交替仍仅为视觉排版。

Python 写入端与 Swift 读取端都检查：角色/段 ID、唯一性、每段恰好一个归属、引用角色存在、本段画面引用有效、high 至少两个不同的本段画面，以及显示姓名与角色记录一致。结构校验不能证明模型判断正确。

每包保留 character-input.json、character-analysis.json、character-frames、提示词副本与 SHA。角色提示词哈希和作品提示加入缓存条件；旧包不覆盖，旧包未知身份仍兼容。已接入校对 UI：可在词边界拆分跨说话人段落并显式指定角色，保存后重新分析。尚无音频 diarization、声纹跨片复用或自动按声纹拆分。
